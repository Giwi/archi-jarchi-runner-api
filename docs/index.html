Headless Archi · REST

Query Archi models on demand.

A small TypeScript + Node.js service that drives Archi 5.6 in headless mode with the jArchi scripting and coArchi collaboration plugins, and returns the script output as JSON.

Archi 5.6.0 jArchi 1.11.0 coArchi 0.9.7

# Overview

One HTTP call, one isolated Archi run.

POST /api/run -> queue (semaphore) -> Archi ACLI + jArchi + coArchi -> stdout + result file -> JSON response

Isolated runs

Each request gets its own scratch directory and workspace, so concurrent runs never share state.

Bounded resources

A semaphore caps parallel JVMs and a hard timeout kills runaway scripts.

Git-backed repos

Models and scripts are cloned and synced as sub-folders of /models and /scripts, over HTTPS with an access token.

# Quickstart

Fetch the binaries, build once, run anywhere.

1. Fetch Archi and coArchi

# downloads into vendor/ (git-ignored)
scripts/fetch-archi.sh

jArchi's binary is not publicly downloadable. Drop the provided *.archiplugin into vendor/plugins/, set JARCHI_URL, or build it from source (see below).

2. Build and run with Docker Compose

docker compose up --build

3. Call the API

curl -s http://localhost:3000/api/run \
  -H 'content-type: application/json' \
  -d '{
    "correlationId": "demo-1",
    "model": "my-model",
    "script": "archiServer.setResult({ elements: $(\".archimate-element\").size() });"
  }'

# API

Run a script, or manage the git repos behind it.

POST /api/run

Execute a jArchi script against a model and return its output.

Request

{
  "correlationId": "string",
  "script":        "jArchi script source",
  "model":         "path inside the /models volume"
}
FieldTypeDescription
correlationIdstringEchoed back in the response.
scriptstringjArchi source, run with --script.runScript.
modelstringResolved inside /models. A directory loads as a coArchi repository (--modelrepository.loadModel); a file loads with --loadModel. Path traversal is rejected.

Response

{
  "correlationId": "demo-1",
  "stdout":        "...",
  "stderr":        "...",
  "exitCode":      0,
  "result": {
    "file":      "/var/archi/runs/run-xxxx/result.json",
    "encoding":  "json",
    "content":   { "any": "parsed JSON, text, or base64" },
    "size":      42,
    "truncated": false
  }
}

result is null when a script does not advertise a result file. A run that exceeds the timeout returns 504 with the same shape.

GET /health

Returns { "status": "ok" }. Used by the container healthcheck.

GET /openapi.json

OpenAPI 3.0 document describing every endpoint. Point your own Swagger UI or client generator at it.

Result convention

A script advertises a result file by printing a JSON object with a resultFile key (aliases: result_file, result). Relative paths resolve against the run directory.

Every script gets a small prelude:

archiServer = {
  correlationId: "demo-1",
  runDir:        "/var/archi/runs/run-xxxx",
  resultFile:    "/var/archi/runs/run-xxxx/result.json",
  // writes result.json and prints { "resultFile": ... }
  setResult: function (value) { /* ... */ }
};
sequenceDiagram
  autonumber
  participant C as Client

  C->>S: POST /api/run
  S->>S: validate + acquire semaphore

# Repositories

Models and scripts are git-managed sub-folders of the mounted volumes. Add over HTTPS with an access token, sync, and remove by id.

flowchart LR
  add["POST /api/models clone url"] --> ready["/models/{id} git repo"]
  ready --> run["POST /api/run model = id"]
  ready --> sync["POST /api/models/:id/sync fetch + ff-only"]
  sync --> ready
  ready --> del["DELETE /api/models/:id"]

Add a repository

curl -s http://localhost:3000/api/models \
  -H 'content-type: application/json' \
  -d '{
    "url": "https://git.example.com/org/my-model.git",
    "id": "my-model",
    "branch": "main",
    "username": "oauth2",
    "token": "glpat-xxxxxxxx"
  }'
FieldRequiredDescription
urlyeshttp(s):// git URL. A token may be embedded (https://oauth2:TOKEN@host/org/repo.git). SSH is not supported.
idnoFolder name. Derived from the URL's last segment. Must match [A-Za-z0-9][A-Za-z0-9._-]*.
branchnoBranch to check out; defaults to the remote HEAD.
usernamenoDefaults to oauth2 when only a token is given (works for GitHub and GitLab).
tokennoAccess token, sent as the password.

Returns 201 with the repository object, or 409 if the id exists:

{
  "id":      "my-model",
  "kind":    "model",
  "path":    "/models/my-model",
  "url":     "https://git.example.com/org/my-model.git",
  "branch":  "main",
  "commit":  "7fd1a60b01f9",
  "subject": "Merge pull request #6",
  "date":    "2012-03-06T15:06:50-08:00",
  "dirty":   false
}

Sync & remove

  • POST /:id/sync: git fetch --prune then a fast-forward-only merge. Returns the object plus updated and previousCommit. Non-fast-forward local commits are refused.
  • DELETE /:id: deletes the folder and returns 204.
Tokens are never written to .git/config: the remote URL is stored sanitized and the token lives in <repo>/.git/archi-server-credentials.json (mode 0600) so sync stays non-interactive. git runs through an askpass helper, so the token never appears in process arguments.
StatusWhen
400Invalid body, non-http(s) URL, bad id or branch.
404Unknown repository id.
409Id exists, folder is not a git repo, or detached HEAD.
502git failed (its stderr is returned in details).
504git exceeded ARCHI_GIT_TIMEOUT_MS.

Volumes

/scripts → jArchi user scripts folder (git-managed script repos).
/models → coArchi repositories and/or .archimate files.

Heap handling

The entrypoint injects -Xms/-Xmx into Archi.ini at start, so no JVM flags leak onto stderr.

# Notes & limitations

  • Each run starts a fresh JVM. Keep ARCHI_MAX_CONCURRENCY low.
  • The image runs as non-root user archi (uid 1001, override with --build-arg ARCHI_UID=$(id -u)). /models and /scripts must be writable by that uid so repositories can be cloned and synced.
  • Repository auth is HTTPS + access token only (no SSH). Tokens live under <repo>/.git/ with mode 0600.
  • CI typechecks and runs the unit tests on every push and PR; the image is published to GHCR only on v* tag commits.
  • Directory models must already be coArchi/GRAFICO repositories (contain model/folder.xml); otherwise coArchi reports an error in stderr.
  • Archi writes a harmless SLF4J(W): No SLF4J providers were found. line to stderr. Silence it with JAVA_TOOL_OPTIONS=-Dslf4j.internal.verbosity=ERROR if desired.
